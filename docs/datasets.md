# Datasets

Datasets are **never committed to git**. Each team member downloads them with `ml/scripts/download.py`, which verifies a SHA-256 checksum so everyone trains on byte-identical data. Only aggregate statistics and figures (in `ml/reports/`) are committed.

### Terms of use (as stated by the data providers, read 2026-11-08)
- The providers state the dataset is free to use.
- **Citation:** put the dataset's URL (above) in any publication, and cite: Feng, M., Heffernan, N.T., & Koedinger, K.R. (2009). *Addressing the assessment challenge in an Intelligent Tutoring System that tutors as it assesses.* User Modeling and User-Adapted Interaction, 19, 243–266. Acknowledge the ASSISTments TestBed.
- The site's general terms page also sets these conditions:
  1. Don't use the data to try to identify students. If identifying information is found, delete it and inform ASSISTments.
  2. **Don't give the data to anyone else**, and use it only for the stated purpose. This is why the repo stores only the download script and checksum, never the file.
  3. Papers using the data are expected to make their data handling and algorithms public. The terms say that if you don't want to share your source code, you can't use this data. **If the team publishes a paper, the ML code must be public.**
- **Action for the team:** each member should read the terms page themselves (https://sites.google.com/site/assistmentsdata/termsofuseforusingdata) before downloading.

### Raw columns used
| Column | Meaning (per the providers) | Used as |
|---|---|---|
| `order_id` | Chronological ID of the problem log | Ordering (the only clock) |
| `user_id` | Student ID | `student_id` |
| `problem_id` | Problem ID | `item_id` |
| `skill_id` | Skill tag; multi-skill problems are collapsed to e.g. `1_13` in this version | `concept_id` |
| `original` | 1 = main problem, 0 = scaffolding sub-question | Filter |
| `correct` | 1 = correct on first attempt; 0 = incorrect or asked for help first | Label |
| `attempt_count`, `hint_count` | Attempts and hints on the problem | Kept (not used as features: they're only known after answering) |
| `ms_first_response` | Time to first response in ms | `response_ms` |
| `tutor_mode`, `answer_type` | Mode and answer format | Filters |

### Cleaning rules and why
| Rule | Reason |
|---|---|
| Drop rows with no skill tag | Knowledge tracing needs a concept per interaction |
| Drop `answer_type = open_response` | These are marked by rule, not by the student's answer, so their labels carry no signal (all 8 are 0 in this file) |
| Keep `tutor_mode = tutor` | Test-mode rows had no feedback and are a different situation |
| Keep main problems only (`original = 1`) | MENTORX has no scaffolding sub-questions. Use `--include-scaffolding` to match papers that keep every row |
| `ms_first_response ≤ 0` → missing | Impossible values (317 rows in the raw file) |
| Repeated (student, problem) pairs are **kept** | They're genuine retries in different assignments (different `assignment_id` and `order_id`) |

Row counts at each step are in the [cleaning table](../ml/reports/eda/assist2009/cleaning.md), generated by `clean.py`.

### Known limitations (and what they mean for MENTORX)
1. **No timestamps.** Only order is known, so time-since-last-practice features (which drive mastery decay and revision) **can't be learned from this dataset.** → A dataset with real timestamps (EdNet, §2) is required for those features.
2. **Different domain** (school maths vs undergraduate ML) and **different item format** (mostly free-response algebra vs MENTORX's 4-option MCQ, where guessing gives 25%). → Only concept-agnostic features are transferred, and performance on MENTORX's own data is measured separately after the pilot.
3. **Mastery-mode stopping rule** (a student stops after 3 correct in a row) creates survivor bias in pooled learning curves. → See the EDA report; models must condition on individual history.
4. **Collapsed multi-skill tags** are treated as their own concepts (e.g. `1_13`), which slightly inflates the concept count.

### Sample and cleaning
- **Sample:** 10,000 students drawn uniformly at random (seed 42) from the 784,309 student files, read directly from the zip. That gives 1.14 M answers, the same order of magnitude as published benchmarks, and it trains on a laptop. Change `--n-students` for a bigger sample.
- `correct` = the student's answer letter equals `correct_answer` in `questions.csv`.
- **Concept** = the question's full tag set (e.g. `179;53;183`) treated as one concept, consistent with the collapsed multi-skill tags used for ASSISTments. That gives 1,779 concepts in the sample.
- Ordering: by timestamp, with the original file order breaking ties (questions in one bundle share a timestamp).
- Dropped: rows with no submitted answer (269). Every question in the sample was found in `questions.csv`.
- `elapsed_time ≤ 0` → missing response time.
- Timestamps are shifted by the providers for privacy. Only **differences** are used (time since last practice), which shifting doesn't change.

### Limitations
1. Different domain (English test prep) and a population of self-motivated app users rather than a class.
2. Questions come in bundles that are answered together, so "seconds since the previous interaction" is often 0 inside a bundle.
3. Many tag-set concepts are small, so per-concept models like BKT have less data per concept than in ASSISTments.

## 4. FoundationalASSIST (Mathematics tutor, MENTORX v2)

| | |
|---|---|
| Purpose in MENTORX | The Mathematics subject: skills, questions, answer keys, historical difficulty, and the training data of the DKT-Q / DKT models served by `/api/v2` |
| Source | https://huggingface.co/datasets/ASSISTments/FoundationalASSIST (gated: log in and accept the terms) |
| Paper | Worden, Heffernan, Heffernan & Sonkar. *FoundationalASSIST: An Educational Dataset for Foundational Knowledge Tracing and Pedagogical Grounding of LLMs.* AIED 2026, arXiv:2602.00070 |
| Licence | **CC BY-NC 4.0**, research and educational use, following the providers' responsible-use guidelines |
| Size | 5,000 students, ~1.72M first attempts, 3,395 problems (Illustrative Mathematics, grades 6–8), 224 skills (Common Core codes) |
| Files used | `Problems.csv` and `Skills.csv` (seeding the app); `Interactions.csv` (model training and difficulty statistics only) |
| Label | `discrete_score = 1` only for a first-attempt correct answer with **no hint and the answer not shown** |

### What the app keeps and why
- The raw CSVs are **never committed**. `backend/scripts/seed_math.py --data-dir <folder>` loads them. CI uses a small synthetic dataset in the same format (`backend/tests/tutor/conftest.py`).
- Every question is stored. A question is **served** only if it maps to exactly one skill, is Numeric (one blank), Multiple Choice or Check All That Apply, has a parseable answer key, and has no image or unrenderable maths layout. That leaves 1,942 of 3,368 questions; the admin page lists the reason for every exclusion.
- A skill is offered when it has at least 5 servable questions (90 of 224 skills).
- Question difficulty comes from **training students only** (`model_artifacts/foundationalassist/question_stats.json`): easy ≥ 75% first-attempt success, medium 45–75%, hard < 45%, and "unrated" with fewer than 10 training answers.
- Question HTML is rebuilt from an allowlist (`app/tutor/html.py`): no links, images, scripts, styles or event handlers survive. MathML is kept.

### Known limitations
- Grade 6–8 maths only. The trained models know these skill and question IDs, so they cannot score other subjects.
- The dataset has no per-question hints, videos or worked solutions. Hints are skill-level concept reminders, and notes and worked examples are original MENTORX content for 18 core standards.
